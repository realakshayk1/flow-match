# Evaluation Protocol

## Approved Benchmarks

- PoseBusters (primary OOD physical validity benchmark)
- CASF-2016 cross-docking

## Excluded Benchmarks

- LIT-PCBA is excluded due published leakage/redundancy concerns that can overstate model quality via memorization effects.

## Phase 1 Execution Policy

- Run raw and UFF post-processed PoseBusters evaluations from the same checkpoint and split.
- Keep command args identical across runs except `--uff_postprocess`.
- Publish:
  - per-complex raw tables
  - summary json files
  - comparison artifact generated by `scripts/compare_posebusters_runs.py`

## Throughput Policy (Phase 2)

- Use one canonical ligand manifest per run and reuse the exact ligand order across all backends (Flow-Match CPU/GPU, Vina, GNINA).
- Apply identical timing rules to every backend: same warmup count, same measured repeat count, wall-clock timing around only backend execution.
- Persist benchmark artifacts under `results/phase2/<run_id>/`: `raw_timings.csv`, `summary.json`, `summary.md`, and the exact `ligand_manifest_used.csv`.
- Report per-backend mean/std/median/p95 ms per ligand, throughput (ligands/s), failure/skipped counts, and speedup ratio vs a declared reference backend.
- Run `scripts/bench/profile_benchmark.py` at least once per configuration to capture stage-level breakdown and include one optimization recommendation derived from the profile.
- Document environment readiness (binary availability and device visibility) alongside benchmark outputs so missing dependencies are explicit.

## Phase 4 Methodology (Real-Target Screening)

- **Default target:** CDK2.
  - Rationale: CDK2 offers a well-behaved kinase-focused active set for early enrichment sanity checks and rapid iteration of screening plumbing before scaling to larger production libraries.
- **Pipeline contracts:**
  1. Build/clean/filter library with `scripts/screening/build_library.py` using an input CSV (`compound_id`, `smiles`) and producing:
     - cleaned library (`std_smiles` + descriptors)
     - filter log
     - stats JSON
  2. Run target-centric ranking with `scripts/screening/run_screen.py` and produce:
     - ranked hits CSV (`rank`, `predicted_score_kcal_mol`)
     - runtime accounting JSON (total wall-time, throughput, per-ligand latency stats)
  3. Evaluate enrichment with `scripts/screening/evaluate_enrichment.py` using known actives mapping and produce:
     - EF1% summary JSON
     - activity-annotated ranking CSV
  4. Interpret top hits with `scripts/screening/analyze_top_hits.py` and produce:
     - top-hit novelty/descriptors CSV
     - markdown report scaffold for medicinal chemistry notes
- **Guardrail:** Phase 4 commits should include metadata/templates and generated summary artifacts only; do not commit large raw screening blobs unless explicitly requested.

## Cross-Docking Policy (Phase 3)

- Build a CASF-style manifest grouped by `target_id` using `scripts/crossdock/prepare_casf_crossdock.py`.
- Use one protocol for both model and Vina runners (same pair manifest, same evaluator).
- Report top-1 RMSD < 2A overall and per-target where possible.
- Keep receptor-selection assumptions explicit in artifact metadata.

## Real-Target Screening Policy (Phase 4)

- Target should be fixed per run (`cdk2` or `egfr`) with explicit active-set provenance.
- Library build must log standardization/filter decisions and rejection reasons.
- Screening runtime must include wall-clock and compounds/sec.
- EF1% claims require explicit active mapping and random-baseline definition.
- Top-hit interpretation must include novelty proxy (e.g., Tanimoto to known actives) and basic drug-like descriptors.

## Output Layout (Integration Convention)

- Phase 1/2 in-progress artifacts are currently written under `eval/`.
- Final interview-facing artifacts should be copied or regenerated under `results/phase1` through `results/phase4`.

## Cross-Docking Protocol (Phase 3)

- Input index: CSV with `complex_id,target_id,receptor_pdb,ligand_sdf` (paths can be relative to a provided root).
- Pair construction: group by `target_id`; create receptor-ligand pairs across group members; default excludes self-docking (`receptor_complex_id == ligand_complex_id`) unless explicitly enabled.
- Receptor choice assumption: each receptor is the exact structure listed in `receptor_pdb` for that complex (no induced-fit refinement or receptor ensemble averaging).
- Reference pose assumption: `reference_ligand_sdf` in the generated manifest is treated as already aligned in the receptor coordinate frame; no extra alignment step is applied in Phase 3 scripts.
- Model runner (`scripts/crossdock/run_model_crossdock.py`):
  - Uses receptor native ligand centroid (`receptor_native_ligand_sdf`) as pocket center.
  - Extracts a fixed-radius pocket (default 10 A) and runs Flow-Match with fixed inference steps.
- Vina runner (`scripts/crossdock/run_vina_crossdock.py`):
  - Uses the same centroid source and fixed search box (default 20 A cube) to keep model-vs-vina settings comparable.
  - Requires `receptor_pdbqt` and `ligand_pdbqt` columns for non-dry runs.
- Unified scoring (`scripts/crossdock/evaluate_crossdock.py`):
  - Computes top-1 success at RMSD < 2 A.
  - Reports overall and per-target metrics on common comparable pairs (intersection of pair IDs from both engines).
